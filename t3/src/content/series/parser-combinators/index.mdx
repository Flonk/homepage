<DeckCard>
  ## Parser Combinators

  **Parsing** is the act of taking less structured input like text, and turning it into more structured data, like objects.

  Many of you will be familiar with using regex to parse text, and some of you might know about tree-sitter, a heavy-duty parsing library which powers the syntax highlighting in your code editor.

  But regex gets messy on complex tasks, and tree-sitter often is overkill -- for this middle ground, **parser combinators** are perfect. Not many people know about them, so allow me to show you!
</DeckCard>

<DeckCard vizProps={{ phase: "type" }}>
  ## The partial parser

  The smallest unit of parsing we'll be looking at is the **partial parser**. It gets to decide where to cut the input string, and then it returns a tuple consisting of *whatever* and the rest of the string.

  It can be any old function, as long as it returns such a tuple! It can even use regex inside.

  <CodeDefinition name="pInteger">

  ```typescript
  const pInteger: Parser<number> = (input: string) => {
    const match = input.match(/^\d+/);
    if (match == null) throw new Error();

    const digits = match[0];
    return [Number(digits), input.substring(digits.length)];
  };
  ```

  </CodeDefinition>
</DeckCard>

  ## Chaining

  A single parser function won't do much on its own; but by applying multiple parsers in sequence, we can consume the entire input step by step.

  <CodeDefinition name="pHello">

  ```typescript
  const pHello: Parser<string> = (input: string) => {
    if (!input.startsWith("Hello")) throw new Error();

    return ["Hello", input.substring(5)];
  };
  ```

  </CodeDefinition>

  <CodeDefinition name="pIgnoreWhitespace" hue={1}>

  ```typescript
  const pIgnoreWhitespace: Parser<null> = (input: string) => {
    const match = input.match(/^\s+/);
    if (match == null) throw new Error();

    const spaces = match[0];
    return [null, input.substring(spaces.length)];
  };
  ```

  </CodeDefinition>

  <CodeDefinition name="pInteger" hue={2}>

  ```typescript
  const pInteger: Parser<number> = (input: string) => {
    const match = input.match(/^\d+/);
    if (match == null) throw new Error();

    const digits = match[0];
    return [Number(digits), input.substring(digits.length)];
  };
  ```

  </CodeDefinition>

  ```typescript
  const [token1, input2] = pHello("Hello 100");
  const [token2, input3] = pIgnoreWhitespace(input2);
  const [token3, input4] = pInteger(input3);

  console.log(token1, token2, token3); // "Hello", null, 100
  console.log(input4); // empty!
  ```

</DeckCard>

<DeckCard vizProps={{ phase: "chain-one" }}>
  ## Chaining

  Or, and this is where the real power of partial parsers comes in: we wrap the chain up as a new parser of its own.

  <CodeDefinition name="pHello100" open>

  ```typescript
  const pHello100: Parser<[string, null, number]> = (input: string) => {
    const [hello, rest1] = pHello(input);
    const [space, rest2] = pIgnoreWhitespace(rest1);
    const [number, rest3] = pInteger(rest2);

    return [[hello, space, number], rest3];
  };
  ```

  </CodeDefinition>
</DeckCard>

<DeckCard vizProps={{ phase: "seq-type" }}>
  ## pSeq

  Or we generalize even further and provide a function that does the chaining! "Feeding the rest of the string into the next parser" is super generic after all, and doesn't really depend on what any single parser does.

  Getting the types right is tricky, but TypeScript is perfectly capable of expressing these complex variadic types.

  <CodeDefinition name="pSeq">

  ```typescript
  type Parsers<T extends unknown[]> = { [K in keyof T]: Parser<T[K]> };

  const pSeq = <T extends unknown[]>(...parsers: Parsers<T>): Parser<T> =>
    (input) => {
      const results = [] as unknown as T;
      let rest = input;
      for (const p of parsers) {
        const [val, next] = (p as Parser<unknown>)(rest);
        results.push(val);
        rest = next;
      }
      return [results, rest];
    };
  ```

  </CodeDefinition>
</DeckCard>

<DeckCard>
  ## Combinators

  Since `pSeq` combines many parsers into a new parser, we call it a **parser combinator**.

  Take a moment to appreciate the functional madness going on: `pSeq` is a function that takes parsers, which are functions, and it returns another parser, which is also a function.

  And only then do we actually start the parsing, by calling the resulting function with data.

  It's like we are building up this construct of nested functions to create a complex program. Kinda cool!
</DeckCard>

<DeckCard vizProps={{ phase: "unfold" }}>
  ## By the way

  If splitting a string into many tokens feels somehow related to `.reduce` then you have good instincts. What we are doing here is actually the dual, which is called an *unfold* in functional circles (`reduce` is referred to as a *fold*).

  While a fold uses intermediate state -- the accumulator -- to combine
  a list of things into one, an unfold uses intermediate state to split one thing into many.

  Yay, maths!
</DeckCard>

  ## Tuples are unwieldy

  If the point of parsing is to get structured, often human-readable data out of raw strings, then a tuple of values like `["Hello", null, 100]` can hardly be the end goal.

  We could of course map over the result to transform it into a more convenient shape.

  ```typescript
  const pHello100 = pSeq(...);
  const [result, rest] = pHello100("Hello 100");

  console.log(result); // ["Hello", null, 100]

  const parsed = {
    greeting: result[0],
    who: result[2],
  };
  ```
</DeckCard>

<DeckCard vizProps={{ phase: "map" }}>
  ## pMap

  But this is not in the spirit of parser combinators! Like before, we can also wrap the mapping into a new parser combinator itself.

  `pMap` takes a parser and a function; the function will be applied
  to the eventual result after parsing.

  <CodeDefinition name="pMap">

  ```typescript
  const pMap = <T, R>(parser: Parser<T>, fn: (value: T) => R): Parser<R> =>
    (input: string) => {
      const [value, rest] = parser(input);
      return [fn(value), rest];
    };
  ```

  </CodeDefinition>

  ```typescript
  const pGreeting = pMap(
    pHello100,
    ([greeting, _, who]) => ({ greeting, who }),
  );

  const [parsed, rest] = pGreeting("Hello 100");

  console.log(parsed); // { greeting: "Hello", who: 100 }
  ```
</DeckCard>

<DeckCard vizProps={{ phase: "repeat" }}>
  ## pRepeat

  Before we hop into a practical example, let me show the third fundamental parser combinator: `pRepeat` -- it takes a given 
  parser and applies it over and over again until it can't.

  It's the `*` of regex, as a combinator!

  <CodeDefinition name="pRepeat">

  ```typescript
  const pRepeat = <T>(parser: Parser<T>): Parser<T[]> =>
    (input: string) => {
      const values: T[] = [];
      let rest = input;
      while (true) {
        try {
          const [value, next] = parser(rest);
          values.push(value);
          rest = next;
        } catch {
          return [values, rest];
        }
      }
    };
  ```

  </CodeDefinition>

  <CodeDefinition name="pNumber">

  ```typescript
  const pNumber: Parser<number> = (input: string) => {
    const match = input.match(/^\d+/);
    if (match == null) throw new Error();

    const digits = match[0];
    return [Number(digits), input.substring(digits.length)];
  };
  ```

  </CodeDefinition>

  <CodeDefinition name="pSemicolon">

  ```typescript
  const pSemicolon: Parser<string> = (input: string) => {
    if (!input.startsWith(";")) throw new Error();

    return [";", input.substring(1)];
  };
  ```

  </CodeDefinition>

  ```typescript
  const pNumberCsv = pRepeat(pSeq(pNumber, pSemicolon));

  pNumberCsv("10;20;30;");
  // [[[10, ";"], [20, ";"], [30, ";"]], ""]
  ```
</DeckCard>

  ## Bits and Bobs

  We have some recurring things in this output like decimal numbers or IP addresses. So let's set those up first.

  <CodeDefinition name="pString">

  ```typescript
  // Exact text, like "PING"
  const pString = (text: string): Parser<string> => (input: string) => {
    if (!input.startsWith(text)) throw new Error();

    return [text, input.substring(text.length)];
  };
  ```

  </CodeDefinition>

  <CodeDefinition name="pInteger">

  ```typescript
  // Whole numbers, like 64
  const pInteger: Parser<number> = (input: string) => {
    const match = input.match(/^\d+/);
    if (match == null) throw new Error();

    const digits = match[0];
    return [Number(digits), input.substring(digits.length)];
  };
  ```

  </CodeDefinition>

  <CodeDefinition name="pDecimal">

  ```typescript
  // Numbers with an optional fraction, like 68.7
  const pDecimal: Parser<number> = (input: string) => {
    const match = input.match(/^\d+(\.\d+)?/);
    if (match == null) throw new Error();

    const digits = match[0];
    return [Number(digits), input.substring(digits.length)];
  };
  ```

  </CodeDefinition>

  ## Go give it a try

  In a single post we built a fairly complicated parser from literally zero, and a hand-rolled parser combinator library along the way!

  It's much easier to create correct and maintainable parsers this way than with a regex; once you start nesting `pSeq` calls, the equivalent regex would become an unreadable mess, while the combinator approach gives you something squeaky clean.

  In case you are missing fancier features like backtracking or lookahead, rest assured that parser combinators can handle those scenarios as well, since at the end of the day it's all just functions composed together.
